第 1 步：Padding 零填充 pads = [1,1,1,1]

输入特征图 32×32。四周「生长」出 1 圈 0 填充格（pad 后 34×34），使窗口在边缘位置也能完整取到 3×3 邻域。

输入特征图（单通道） 32×32 → pad 1 → 34×34

// 填充后尺寸
W_out = W + 2P = 32 + 2×1 = 34
H_out = H + 2P = 32 + 2×1 = 34
随后 stride=2 滑窗：⌊(34−3)/2⌋+1 = 16×16（真实模型 640→642→320 同理）

第 2 步：滑窗卷积（3 通道同步） kernel 3×3 · stride 2

R/G/B 三个通道（各 32×32，pad 后 34×34）上，3×3 窗口以 stride=2 同步滑动。每停一处：27 个数逐元素相乘求和、加 bias，写入输出格。输出 16×16。

第 4 步：32 个卷积核 → 32 个输出通道 weight [32,3,3,3]

上面演示的只是「第 0 个卷积核」。完整层有 32 个不同的核：每个核（3×3×3 = 27 个权重 + 1 个偏置）扫过整个输入，产出一张 16×16 特征图，32 张堆叠成输出张量。

卷积核 0 / 32  ⇒  输出通道 0 / 32
每生成 1 个核 → 产出 1 张 16×16 特征图薄片 → 堆叠为 1×32×16×16

第 5 步：3D 全景演示 · 体素方块版（可旋转 / 平移 / 缩放视角） Three.js · 3×32×32 → 32×16×16

复刻 animatedai.github.io 的体素（voxel）叙事：浅色展台上，左侧输入体由 32×32×3 个灰色体素堆成（深度 3 层 = R/G/B 通道，前面板带淡青色调；真实模型第一层输入为 640×640，此处按全局配置 Global_CFG 演示，计算结构完全一致），四周多出一圈画小一号的浅色虚拟格 = pads 1,1,1,1 在上下左右各扩 1 格（pad 后 34×34）；一个 3×3×3 白色高亮滑窗以 stride=2 在 pad 后的输入面上跳动扫描，边缘位置正好探入 pad 圈，共 16×16 = 256 个位置（真实模型为 320×320；与真实模型一致：pad 后尺寸为偶数时，最右/最下一圈 pad 不会被 stride 2 的窗口扫到）；中间水平一排、互不重叠地排列 16 个彩色 3×3×3 卷积核（红 → 品红 HSL 渐变，与真实权重 model.0.conv.weight [16,3,3,3] 一一对应），每个体素的亮度编码真实权重值（正值亮、负值暗）；滑窗每扫过一整行 → 当前卷积核整体脉冲一下 → 右侧黑色线框输出盒（容量 32×16×16：沿 x 轴 32 层 = 真实模型的 32 个输出通道，本演示用 16 个真实核填前 16 层）对应位置逐格长出核色体素；一个核扫满 256 格填完一层，换下一个核填下一层，16 层填满即止。实际模型中该 Conv 之后还接 Sigmoid+Mul（即 SiLU 激活）。左键拖拽旋转视角，右键/Shift 拖拽平移，滚轮缩放。

这一层在 YOLO26 中的作用：以 stride=2 将 32×32 的 RGB 图像下采样 2 倍到 16×16， 同时用 32 个 3×3 卷积核提取边缘、颜色对比等低级特征，把 3 通道像素信息压缩编码为 32 通道特征表示， 供后续 Backbone 逐层抽象。整个第一层仅需 896 个参数、约 0.4 MFLOPs 计算量（此处为演示配置；真实模型 640×640 时为 896 参数、约 0.18 GFLOPs）。
